## 1. 背景与问题

| 现状 | 问题 |
|------|------|
| 音/视频可建索引，ASR 可出全文 | 硅基 SenseVoice 常无可靠句级 `segments`，文稿常呈「一坨」 |
| 播放器有「摘要」Tab | 目前多为全书一句话/概览，**不能按语义段点选跳播** |
| 用户期望 | 类似文本摘要：先理解大意分段，再定位到「相关内容处」播放 |

**产品决策（已口头确认）：**

- **不要**固定切 5 段（或任意写死 N）  
- **要** AI **按大意**分段，有多少主题就多少段  
- **不要**本期内做歌词级 / 电视剧逐句字幕（需换句级 ASR）  
- **要** 点摘要章节 → seek 播放  

---

## 2. 目标

### 2.1 用户目标

打开网盘内音/视频 → 建立索引 → 在「摘要」看到 **按主题划分的章节列表** → 点击某章 → 从该主题大致开始的时间点播放。

### 2.2 非目标（本期）

- 句级/字级字幕卡点、换 ASR 供应商  
- 固定均分时间窗当「章节」  
- 外链视频、分享页媒体摘要  
- F-41 文稿纠偏  

---

## 3. 用户体验

### 3.1 主路径

1. 双击音/视频打开 `VideoPlayerDialog`  
2. 点「建立索引」（体裁可沿用现有 media 占位，如 novel）  
3. 等待转写 + 摘要完成（进度文案可区分「转写中 / 生成章节摘要中」）  
4. 切「摘要」Tab：见全书一句话/总览 + **可点击章节列表**  
5. 点击某一章 → `currentTime = startMs/1000` 并播放  
6. 「文稿」Tab 仍展示转写全文（可仍为一坨；不作为本需求主验收）

### 3.2 界面要点

| 元素 | 行为 |
|------|------|
| 章节行 | 显示序号、标题、时间范围（或起始时间）、短摘要 |
| 点击章节 | seek + play；可选高亮当前章 |
| 空态 | 索引未完成 / 无章节：明确文案 |
| 段数 | UI **不写死**「共 5 段」；随 API 返回条数渲染 |

### 3.3 失败与边界

| 情况 | 处理 |
|------|------|
| ASR 失败 | 与现网一致，索引 failed |
| 有全文、无时长 | 可出章节文案，跳转禁用或仅展示 |
| LLM 章节为空 | 降级：仅全书 overview；或合成 1 条「全文」章从 0 起 |
| 章节过多 | 服务端裁剪到上限（建议 12） |

---

## 4. 概念模型

```
媒体文件
  → ASR 全文 transcriptText（可无句级时间）
  → durationMs（ffprobe）
  → LLM：按语义输出 chapters[]（段数不定）
  → 映射：章节在文稿中的位置 → startMs / endMs
  → 持久化 + GET summary
  → 播放器点击 seek
```

**一句话：** ASR 负责「听到什么字」；LLM 负责「大意切几段」；时长 × 文稿位置负责「大概从哪一秒听」。

---

## 5. 语义分段规则

| 规则 | 设计 |
|------|------|
| 分段依据 | 主题 / 话题变化，非固定字数 |
| 段数 | 模型自定，校验夹在 **1～12** |
| 覆盖 | 章节按时间/比例大致覆盖全文，少大重叠 |
| 字段 | `title`、`summary`、位置（`startRatio`/`endRatio` 或字符下标）、映射后的 `startMs`/`endMs` |
| 全书 | 另保留 `oneLiner`、`overview` |

---

## 6. 时间映射策略（MVP）

**选定：文稿位置比例 × 总时长。**

1. LLM 输出每章在全文中的 `startRatio` / `endRatio`（0～1），或 `startChar` / `endChar`  
2. `startMs = round(startRatio * durationMs)`（字符下标则先除以全文长度）  
3. 校验：排序、裁剪到 `[0, durationMs]`、保证 `endMs > startMs`

**不选（本期）：**

- 固定均分 N 段再摘要（违背「按大意」）  
- 依赖 ASR `segments`（当前常不可用）  
- 先按时间切音频多次 ASR（成本高，作二期备选）

**诚实预期：** 跳转是「主题附近」，不是字幕帧级精确。产品文案可用「约」或直接显示估算时间。

## 7. 与文本摘要（F-03）的关系

| | 文本 F-03 | 本设计 |
|--|-----------|--------|
| 输入 | 文档 chunk | 媒体转写全文 + duration |
| 结构 | Map-Reduce → book/chapter | 媒体专用：语义 chapters + 时间 |
| 交互 | 阅读摘要 | **摘要可驱动播放器 seek** |
| 复用 | `generateObject`、索引 Job、`DocumentSummary` | 同左；**不**强行共用 novel 的 plotPoints 等字段 |

## 8. 数据与 API（设计层）

### 8.1 存储倾向（供实现选型）

**推荐：** 在现有 `DocumentSummary` `type=book` 的 `payload` JSON 中增加：

```json
{
  "oneLiner": "...",
  "overview": "...",
  "mediaChapters": [
    {
      "index": 1,
      "title": "...",
      "summary": "...",
      "startMs": 0,
      "endMs": 120000
    }
  ],
  "durationMs": 600000
}
```

避免新增 Prisma 枚举；文本文档 payload 无 `mediaChapters` 即可。

**备选：** 多条 `type=chapter` + payload 带时间（与文本 chapter 语义易混，需约定 refKey）。

### 8.2 API 倾向

- 复用 `GET /api/files/:id/ai/summary`（默认 book）  
- 响应 `payload` 含 `mediaChapters` 时，前端渲染可点列表  
- 不新增独立「章节跳转」API  

---

## 9. 风险

| 风险 | 缓解 |
|------|------|
| 比例时间偏差大 | Prompt 要求按内容先后；二期可接真 segments |
| LLM 段数失控 | 硬限制 1～12 + 合并校验 |
| 超长文稿超上下文 | 过长则截断/分段摘要再合并章节（实现方案细化） |
| 与现有 novel book schema 冲突 | 媒体走独立 schema 或扩展可选字段，文本文档路径不动 |
