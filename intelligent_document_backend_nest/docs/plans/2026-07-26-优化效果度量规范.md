## 1. 固定流程（每一项 O-xx 都走一遍）

```
① 选固定样本（同一文件 / 同一目录 / 同一操作）
② 采基线（优化前）→ 填「对比记录表」
③ 做改动（只动该项相关代码）
④ 同环境复测（优化后）→ 再填同一表
⑤ 算改善率 → 判定有效 / 无效 / 需回滚
⑥ 在优化清单勾选状态，并贴本次数据摘要
```

**环境要求（前后必须一致）：**

| 项 | 要求 |
|----|------|
| 样本 | 同一 `fileId` / 同一本地文件 / 同一目录规模 |
| 机器 | 同一台开发机；Worker / API 同一套进程配置 |
| 网络 | 尽量同一时段；AI 类注明模型与供应商（SiliconFlow / DeepSeek） |
| 预热 | 第一次可作冷启动单独记；正式对比用「第二次」或明确标注冷/热 |
| 次数 | 同一操作至少 **2 次**，取中位数或均值；异常值注明 |

**判定规则（建议）：**

| 结果 | 条件 |
|------|------|
| ✅ 有效 | 主指标改善 ≥ 预期下限（见各 O 项），且无功能回归 |
| ⚠️ 弱有效 | 有改善但 < 预期；保留代码但记「收益偏小」 |
| ❌ 无效 | 主指标持平或变差 → 回滚或改方案后再测 |

## 3. 怎么采数（通用手段）

### 3.1 Worker / Nest 日志时间戳（AI 索引首选）

索引管线本身有阶段日志，例如：

- `ASR done` / `transcript persisted`
- `Embedding done` / `chunks persisted`
- `Index completed` / `failed`

**做法：**

1. 清空或记下开始前最后一行日志时间  
2. 触发重建索引（或上传触发）  
3. 从日志抄各阶段起止时间，算墙钟秒数  

可选：临时在关键路径打 `console.time` / `Date.now()` 差值（对比完可删或改为 debug 日志）。

### 3.2 浏览器 DevTools（前端 / HTTP）

- Network：接口耗时、传输大小、请求数  
- Performance：首屏 / 滚动卡顿（O-05、O-06）  
- Memory（Chrome）：合并上传前后堆峰值（O-11）

### 3.3 系统侧（内存 / CPU）

- Windows：任务管理器看 `node` 工作集峰值（合并大文件时）  
- 或 PowerShell 简易采样（按需）

### 3.4 业务计数（成本类）

- ASR / Embedding / Chat **调用次数**（日志或供应商控制台）  
- 失败重试是否跳过已完成阶段（O-01）

## 4. 各优化项：基线怎么采 / 后怎么比

### O-01 断点续建

| | |
|--|--|
| **样本** | 一条 **≥5 分钟** 音/视频，且能稳定跑完 ASR（或已知会在 embedding 失败） |
| **主指标** | 第二次失败后「续跑」总墙钟；ASR HTTP **是否再次调用** |
| **辅指标** | Embedding 调用次数；用户操作次数 |
| **基线步骤** | ① 建索引至某阶段后故意失败（或等真实失败）② 点「重新建立索引」③ 记日志：是否重跑 ASR、总耗时 |
| **优化后** | 同文件再走失败→重建；确认 ASR **跳过**，总耗时明显下降 |
| **有效标准** | 续跑时 ASR 不重复；墙钟至少少掉「一整段 ASR」量级 |
| **优化后结果** | ✅ 有效（2026-07-26）。样本约 53:05 视频二次重建 **241s → 174s**（约 -28%）；详见 [metrics/O-01-20260726.md](./metrics/O-01-20260726.md) |

### O-02 向量批量写库

| | |
|--|--|
| **样本** | 同一文本或媒体，chunk 数尽量 **≥30**（块太少看不出批写差） |
| **主指标** | `embedding` 完成后 → `chunks persisted` 的墙钟（或整段 embedding 阶段） |
| **辅指标** | 索引总墙钟；DB 往返次数（若加了日志） |
| **基线步骤** | ① 删索引/force 重建 ② 记 embedding→落库耗时 ③ 重复 2 次取均值 |
| **优化后** | 同文件 force 重建，同指标对比 |
| **有效标准** | 落库段耗时下降（预期数量级：中大文档 **明显缩短**；极小文件可持平） |
| **优化后结果** | 待测 |

### O-03 摘要 Map 并行

| | |
|--|--|
| **样本** | 长文或长媒体，Map 批次数 **≥4**（`SUMMARY_MAP_CHUNK_CHARS` 默认下够长） |
| **主指标** | `summarizing` 阶段墙钟（从进入摘要到摘要完成） |
| **辅指标** | Chat 调用次数（应相近）；总索引时间 |
| **基线 / 后** | 同文件 force；只比 summarizing 段 |
| **有效标准** | summarizing 墙钟下降（并行度 2～3 时常见 **明显短于串行**） |
| **优化后结果** | 待测 |

### O-04 embedMany 批间并行

| | |
|--|--|
| **样本** | chunk 数使 `embedMany` **≥3 批**（受 `EMBEDDING_BATCH_SIZE` 约束） |
| **主指标** | embedding 阶段墙钟 |
| **辅指标** | 429/限流错误次数（变多则并行过大） |
| **有效标准** | embedding 墙钟下降，且无稳定限流失败 |
| **优化后结果** | 待测 |

### O-05 列表分页 + 虚拟滚动

| | |
|--|--|
| **样本** | 单目录 **≥200** 文件（可脚本造数据或用已有大目录） |
| **主指标** | `GET /files`（或列表接口）首包耗时；首屏可交互时间 |
| **辅指标** | 响应 JSON 大小；滚动 60fps 主观/Performance |
| **基线步骤** | DevTools Network 记列表接口；Performance 录打开目录 |
| **有效标准** | 首包耗时与 payload 下降；大目录滚动不长期掉帧 |
| **优化后结果** | 待测 |

### O-06 前端拆包 / 文稿虚拟列表

| | |
|--|--|
| **样本** | 生产 build；带长 `document.chapters` 的媒体页 |
| **主指标** | 首屏 JS 体积（或 LCP/可交互）；章节列表滚动 |
| **基线** | `pnpm build` 看 chunk 体积；浏览器录一次打开播放器 |
| **有效标准** | 首屏相关 chunk 变小或播放器页更轻；长列表滚动更稳 |
| **优化后结果** | 待测 |

### O-07 索引 concurrency 可配

| | |
|--|--|
| **样本** | **同时** 丢 3～5 个索引任务（多文件） |
| **主指标** | 队列全部完成的总墙钟（吞吐） |
| **辅指标** | 单文件耗时（可能略增）；CPU/内存是否可接受 |
| **有效标准** | 多文件总完成时间下降；单机资源不打爆 |
| **优化后结果** | 待测 |

### O-08 预览与索引隔离

| | |
|--|--|
| **样本** | 一边跑重索引，一边点文档预览 |
| **主指标** | 索引中预览接口 P95 / 主观是否卡住 |
| **有效标准** | 重索引时预览仍可用（不再整进程打满） |
| **优化后结果** | 待测 |

### O-09 向量检索

| | |
|--|--|
| **样本** | 固定语料库规模 + 固定查询句 5～10 条 |
| **主指标** | 检索延迟；相关结果命中（人工抽检） |
| **基线** | 现有「拉候选再算」耗时 |
| **有效标准** | 延迟下降或召回质量可接受（按短期/长期方案分别定） |
| **优化后结果** | 待测 |

### O-10 以图搜图

| | |
|--|--|
| **样本** | 固定图库规模；冷启动一次 + 热一次 |
| **主指标** | 冷启动首次搜图耗时；热路径耗时 |
| **有效标准** | 冷启动下降；热路径不回退 |
| **优化后结果** | 待测 |

### O-11 合并上传流式化

| | |
|--|--|
| **样本** | **同一大文件**（建议 ≥200MB，越大越明显），分片数固定 |
| **主指标** | 合并接口耗时；Node 进程 **内存峰值** |
| **辅指标** | 合并期间其它 API 是否卡顿（主观） |
| **基线步骤** | ① 上传至待合并 ② 合并前记下内存 ③ 合并，记耗时与峰值 ④ 重复 2 次 |
| **有效标准** | 内存峰值明显下降（不再近似「整文件进堆」）；耗时不显著变差 |
| **优化后结果** | 待测 |

### O-12 缩略图异步 / 预生成

| | |
|--|--|
| **样本** | 含 **≥20** 视频的目录 |
| **主指标** | 打开目录时列表接口耗时；ffmpeg 是否在请求内同步跑 |
| **辅指标** | 缩略图稍后出现的可接受性（产品） |
| **有效标准** | 列表首包不再等一批 ffmpeg；目录打开明显更快 |
| **优化后结果** | 待测 |

### O-13 回收站批量

| | |
|--|--|
| **样本** | 回收站内 **大文件夹**（子文件多）或多次选中批量 |
| **主指标** | 还原/删除接口耗时；请求次数 |
| **有效标准** | 批量一次完成或总耗时下降；超时/失败率不升 |
| **优化后结果** | 待测 |
